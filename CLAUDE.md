# CLAUDE.md

Project context for Claude Code. Read this before working in this repo.

## 1. Project overview

**Name:** Farmer Assistant (working title)

**What it is:** An AI advisor for farmers, delivered through WhatsApp (Telegram for early testing; an app comes later). A farmer sends a voice note, a text message, or a photo of a sick crop and gets fast, trustworthy advice in their own language.

**Why it exists:** Farmers often can't reach an agronomist quickly. A wrong decision (wrong pesticide, wrong sowing time, selling at the wrong price) can cost a whole season's income.

**Current stage:** Phase 1 (MVP). One crop, one region, one language.

## 2. Scope (MVP)

In scope now:

- Text + voice Q&A in ONE local language
- Photo-based disease / pest detection for ONE crop
- RAG grounded ONLY in trusted agricultural sources
- Safety fallback: "I'm not sure, please contact an expert" when confidence is low
- Interaction logging (with consent) so an expert can review answers

Not in MVP (do not build yet):

- Multiple crops or languages
- Weather, mandi prices, government schemes, reminders, feedback buttons (Phase 2+)
- Mobile app, offline mode, dashboards (later phases)

Do not add features from later phases unless asked.

## 3. The single most important rule: accuracy and safety

This app gives advice that affects real crops, money, and chemical handling. Therefore:

1. **Never invent agricultural advice.** All crop/disease/dosage answers must come from the trusted source documents via RAG. If the sources don't cover it, say so.
2. **Dosage and chemical info is shown exactly as written in the source, with the source named.** Do not paraphrase numbers.
3. **Every answer carries a confidence signal.** Low confidence → recommend a human expert.
4. **Pesticide/chemical questions get extra caution.** Prefer organic/IPM options first; always include safety precautions.
5. **When unsure, defer to an expert. Fail closed, never guess.**

How the code enforces this (keep it that way):

- The **vision step only diagnoses**. It never suggests treatment. Treatment always comes from the RAG step.
- The answer model must return **verbatim quotes** for every dosage and safety instruction. `app/safety/guard.py` checks each quote is really in the retrieved text and shows the quotes to the farmer untranslated with the source name.
- Every number in the answer must appear in the cited source chunks, or the answer is replaced with the expert fallback.
- No retrieved source above the similarity threshold, a low-confidence answer, a low-confidence diagnosis, or a model refusal → expert fallback.
- Fixed safety and fallback messages live in `app/ui_text.py` and are never generated by the LLM.

When touching anything that gives crop/chemical advice, re-read this section and keep the tests in `tests/test_guard.py` passing.

## 4. Architecture

```
Farmer (WhatsApp / Telegram)
      │  voice / text / photo
      ▼
Webhook (FastAPI) ── verify signature, dedupe, ack 200 immediately
      │  background task
      ▼
pipeline.handle_message
      │
      ├─ consent check (first contact)
      ├─ voice  → speech/ STT  (when a provider is configured)
      ├─ photo  → vision/ diagnose (LLM vision, structured output)
      ├─ text   → llm/ understand (scope check + English search query)
      ├─ rag/ retrieve from Chroma (trusted sources only; whole matching sections)
      ├─ llm/ grounded answer (structured: answer, quotes, confidence)
      ├─ safety/ guard (verify quotes + numbers, decide fallback)
      └─ store/ log interaction (content only if consented)
      │
      ▼
Reply on the same channel
```

## 5. Tech stack

- **Backend:** Python 3.11+, FastAPI, uvicorn
- **Messaging:** Telegram Bot API for local testing (polling script, no public URL needed); WhatsApp Cloud API for real users
- **LLM:** selectable with `LLM_PROVIDER`. Default is **Gemini** (`google-genai` SDK, `GEMINI_MODEL`, default `gemini-2.5-flash`; check with `scripts/list_models.py`). **Claude** (`anthropic` SDK, `LLM_MODEL`, default `claude-opus-5-5`, with server-side refusal fallback) is also supported. Both live in `app/llm/client.py` behind one `LLM.parse()` interface that returns a validated Pydantic object; callers pass provider-neutral content (text and `Media` images). Every LLM step uses structured JSON output.
- **Vector DB:** Chroma, embedded (persists to `data/processed/chroma`, no server). Default embedding model is English, so sources are indexed in English and farmer questions are turned into an English search query first.
- **Disease detection:** LLM vision (Gemini or Claude) for now; later a fine-tuned classifier (PlantVillage-style data, then real field photos from users)
- **Speech:** pluggable interface in `app/speech/`; provider not chosen yet (see section 2)
- **Storage:** SQLite (`data/app.db`) for consent and interaction logs in Phase 1. Move to Postgres in Phase 2 when farmer profiles arrive.

If you change any tooling choice, update this section.

## 7. Conventions

- Python 3.11+, type hints. Format with `black`, lint with `ruff`.
- Keep functions small and testable. `main.py` only wires webhooks; logic lives in `pipeline.py` and the packages.
- Secrets only via environment variables. Keep `.env.example` updated; never commit `.env`.
- All prompts and LLM output schemas live in `app/llm/prompts.py` / `app/llm/schemas.py`, not inline.
- Log every interaction (question, retrieved source ids, answer, confidence, fallback reason). Message content is stored only if the farmer consented; user ids are stored as salted hashes, never raw phone numbers.
- Webhooks must return 200 fast and process in the background; WhatsApp retries slow webhooks and will send duplicates. Deduplicate by message id.
- Tests must not call real APIs. Use the fakes in `tests/fakes.py`.
- Add a test when you add a feature.

## 8. How to run

```bash
# setup
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # then fill in keys and Phase 0 decisions

# pull the crop's rows out of the official CIB&RC "Major Uses of Pesticides" PDFs
# (download them into data/sources/raw/ first; see data/sources/README.md)
python scripts/extract_cibrc_crop.py data/sources/raw/cibrc_mup_*.pdf

# index trusted sources (put PDFs/TXT/MD in data/sources/ first)
python scripts/ingest.py

# ask a question from the terminal (no messaging needed)
python scripts/ask.py "my chilli leaves are curling upwards"
python scripts/ask.py --image leaf.jpg "what is this?"

# test with a real Telegram bot, no public URL needed
python scripts/telegram_polling.py

# run the webhook server (WhatsApp / Telegram webhooks)
uvicorn app.main:app --reload

# list Gemini models your key can use (to set GEMINI_MODEL)
python scripts/list_models.py

# run expert-reviewed eval set
python scripts/eval.py

# tests and lint
pytest
ruff check . && black --check .
```

## 9. Roadmap (what's next, not what to build now)

- **Phase 1 (now):** voice/text Q&A + photo disease detection + RAG, one crop/language. Success test: 20–30 real farmers for two weeks, expert reviews a sample of logged answers.
- **Phase 2:** farmer profiles (Postgres), weather-aware advice, crop calendar reminders, mandi prices, feedback buttons.
- **Phase 3:** more crops + second language, scheme finder, pest outbreak alerts, expert-escalation dashboard, better vision model on real field photos.
- **Phase 4:** soil/fertilizer advice, price forecasting, insurance/loan help, marketplace links, offline mode, partner analytics.
